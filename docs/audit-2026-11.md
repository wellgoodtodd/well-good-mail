# Code audit, November 2026 (after 0.7.2)

A read-only look at the whole app: the mail and account code, the screens and styling, and security with the AI Connection. Nothing was changed. File and line numbers are as of 0.7.2.

## Overall

In good shape for its size (about 29,000 lines). TypeScript is on its strictest settings with no unused code, 254 tests pass, the Rust side lints clean, tokens are kept in Windows Credential Manager, email is shown sandboxed with no scripts, and updates are signed. The problems are a handful of real bugs that rarely bite, some security gaps worth closing, memory and speed that will get worse as mailboxes grow, and four files that have got too big to change comfortably.

## Round 1: things that can actually go wrong (one beta, no visible change)

1. **An email can be sent twice.** After sending, saving a follow-up reminder (or clearing the outbox) can fail, and the whole send is then retried a minute later. Fix: once the send succeeds, it counts as sent whatever happens next. (`sender.ts:39`, `mail.ts:1693`)
2. **A request that never answers stops that account syncing until restart.** No time limit on web or IMAP calls. Fix: a time limit on every call. (`platform.ts:8`, `mail.ts:605`)
3. **Archived or read mail can pop back for one sync.** A sync that started before you acted can finish afterwards and write the old state back. Fix: remember changes still on their way and don't let an older sync undo them. (`mail.ts:177, 650`)
4. **The calendar can bring back an event you just edited or deleted**, the same way. Fix: only the newest refresh counts, as search already does. (`mail.ts:1491`)
5. **Outlook drafts: saving deletes the old copy before making the new one**, so a failed save loses the draft. Fix: make first, then delete (IMAP already does this). (`microsoft.ts:224`)
6. **Turning Out of Office off before it has loaded could blank its message.** (`oooStore.ts:179`)
7. **Outlook sign-in: a server hiccup marks the account as needing sign-in.** Only a real sign-in refusal should. (`auth/microsoft.ts:90`)
8. **Opening an attachment skips Windows' "from the internet" protection**, so Word macros, SmartScreen and Protected View don't apply. Fix: mark every saved or opened file as downloaded, and widen the never-open list. (`files.rs:120`)
9. **Blocked remote images can sneak through** with a hidden line break or CSS escape in the address, which lets senders see you opened the email. Fix: check addresses the way the browser reads them. (`render.ts:100`)
10. **AI Connection tidy-ups:** an approval clicked after the AI has given up still runs; a client can skip the pause prompt by using the self-test name; the connection reads a line with no size limit. (`server.ts:134`, `mcp.rs:65, 92`)
11. **Search after:/before: dates are a few hours out** (read as UTC). (`search.ts:94`)
12. **Dragging a panel edge re-draws most of the app on every mouse move** and saves settings each time. Fix: save once when you let go. (`App.tsx:665`)

- Only the latest 200 changes are read, with no paging; mail deleted elsewhere never disappears; moved mail may show twice. (`microsoft.ts:169`)

## Round 3: speed and memory as mailboxes grow

The rule (Todd, 12 Nov): only work on what changed. Anything that hasn't changed stays as it is: not re-drawn, re-counted, re-saved or re-indexed. In practice:

- Keep only the list details in memory (sender, subject, date, flags); load an email's full text from the cache when it's opened, and let it go after.
- Change one email in place rather than copying the whole list; keep a thread index and the counts (unread, sidebar, badge) up to date as each email changes, instead of re-counting everything.
- Re-draw only the rows that changed, and only the rows on screen.
- Save only what changed (one email, one setting), and only once a drag or burst of typing has finished.
- Index an email for search once, when it arrives or changes.
- Remember things that rarely change (calendar addresses, folder lists) instead of asking again every few minutes.

- Every email's full text is held in memory, and the search index keeps up to 20,000 characters of each. Each change copies the whole list, so a big first sync does that a few hundred times.
- Sidebar counts, the unread badge, threads and follow-ups each loop over every email on every change or sync. A thread index and counts kept during sync would remove most of it.
- The message list re-draws every row when any email changes, and has no virtual scrolling.
- iCloud calendars re-discover themselves every 3 minutes; Gmail's first sync fetches recent mail twice.
- The app's main file is 1.4 MB; some heavy parts could load only when needed.

## Round 4: tidy-up (no change in behaviour, done alongside 0.7.3)

- **Split the big files:** `mail.ts` (1,780 lines) into store, accounts, sync, bodies, calendar, actions, contacts, outbox and timers; `Settings.tsx` (1,720) into one file per tab; `Composer.tsx` into autosave, attachments and header; `ComingUp.tsx`'s event pop-up and month view into their own files. Splitting `ComingUp.tsx` first makes creating events (0.7.3) easier to build.
- **Shared controls:** the segmented picker, switch line and radio are copied by hand in Out of Office, the calendar, AI Connection and Reminders. One version in `ui.tsx`.
- **Duplicated helpers:** a date formatter written eight times, repeat-count logic twice, HTML-to-text twice, body merging four times.
- **Stylesheet:** about 20 rules defined twice (the later one quietly wins), about 40 unused classes, 88 colours that bypass the theme, and stacking order numbers with no system. Merge, delete, add colour and layer tokens.
- **Unused code:** a handful of functions nobody calls, and exports only used in their own file.

## Round 5: accessibility and the editor upgrade

- Pop-ups don't return focus to where you were when they close; menus have no arrow keys; message rows and calendar days aren't reachable by keyboard. Fits the accessibility work already on the list.
- The compose editor (Tiptap) has a moderate security notice fixed only in version 3. A proper upgrade, so its own beta with a good test of writing, formatting, signatures and pasting.

## Later

- AI Connection: "Allow for an hour" covers every connected AI app rather than the one that asked; Answer all can approve mixed requests at once.
- The IMAP library is old and unmaintained; a malformed server reply could crash the app. Consider a newer one.
- A few Windows commands (scheduled-send wake, default mail app, saving big files) run on the main thread and can freeze the window briefly.
- Settings lists such as muted threads and blocked senders grow without limit.

## Checked and fine

Token storage, sign-in (PKCE), email sandboxing and link handling, update signing, the app's network permissions (only Google, Microsoft and GitHub), AI permission checks on every tool, rate limiting, Gmail quota back-off, Google token refresh, moving events across accounts (makes before deleting), and effect clean-up in the screens.
